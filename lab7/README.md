### Завдання 5 · Захоплення змінних (вивід і пояснення)

**Фактичний вивід програми:**
```text
1. Змінна після лямбди (перевірка 50 > threshold): False
2. Лічильник циклу for: 3 3 3
3. Цикл foreach: 0 1 2

```

**Пояснення:**

1. **Змінна після лямбди:** Лямбда-вираз у C# захоплює саму змінну (посилання на неї в пам'яті), а не її значення на момент створення делегата. Коли перед викликом делегата ми змінили `threshold` на `1000`, лямбда звернулася до вже оновленого значення, тому перевірка `50 > 1000` повернула `False`.
2. **Лічильник циклу `for`:** У циклі `for` змінна лічильника `i` оголошується один раз на весь цикл, тому всі три створені лямбди захоплюють ту саму змінну. Після завершення циклу `i` дорівнює `3`, і при виклику кожна лямбда повертає саме фінальне значення `3`.
3. **Цикл `foreach`:** Починаючи з C# 5.0, компілятор для кожної нової ітерації циклу `foreach` створює окрему приховану локальну змінну циклу. Через це кожна лямбда захоплює власну копію змінної зі своїм значенням (`0`, `1` і `2`).

**Як виправити пункт 2:** Створити всередині тіла циклу `for` тимчасову локальну копію змінної (`int copy = i;`) і передати в лямбду саме `copy`.
