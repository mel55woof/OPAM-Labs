## Лабораторна робота №8
**Тема:** Алгоритми пошуку та їх порівняння  
**Параметри:** `N = 16, K = 1, a = 1, b = 0, c = 1`

### Завдання 1 · Лінійний пошук
- **Значення X (`"А-00"`):** індекс = `0`, порівнянь = `1`
- **Перший елемент (`"А-00"`):** індекс = `0`, порівнянь = `1`
- **Відсутнє значення (`"Я-99"`):** індекс = `-1`, порівнянь = `100000`

Третій запит виявився найдорожчим із трьох, оскільки за відсутності шуканого елемента лінійний пошук змушений перевірити кожен зі `100 000` елементів масиву до самого кінця.

---

### Завдання 2 · Чотири поломки бінарного пошуку
- **Класичний бінарний пошук:** `X` → `12` порівнянь; перший елемент → `12` порівнянь; відсутній `"Я-99"` → `17` порівнянь.

1. **Поломка 1 (`while (lo < hi)` замість `<=`):**
   - *Фактичний вивід:* при пошуку останнього елемента масиву (`"Я-98"`, індекс `99999`) алгоритм зупинився на позиції `99951` (а на унікальному останньому елементі повернув би `-1`).
   - *Прояв:* цикл припиняється, щойно межі `lo` і `hi` сходяться в одну точку, тому крайній правий елемент діапазону не перевіряється.

2. **Поломка 2 (`lo = mid` замість `mid + 1`):**
   - *Фактичний вивід:* при пошуку відсутнього елемента `"Я-99"` цикл застряг на діапазоні довжиною 2 елементи і був примусово зупинений лічильником після `1000` ітерацій (`результат = -1`).
   - *Прояв:* програма нескінченно зависає, оскільки межі пошуку перестають рухатися.

3. **Поломка 3 (`mid = (lo + hi) / 2`):**
   - *Фактичний вивід:* на масиві розміром `100 000` працює без жодних збоїв.
   - *Прояв:* переповнення типу `int` (`lo + hi > 2 147 483 647`) можливе лише на масивах розміром від `1 073 741 825` елементів (приблизно 1,07 млрд), коли пошук зміщується у праву половину.

4. **Поломка 4 (невідсортований масив):**
   - *Фактичний вивід:* із `100` запитів наявних у масиві значень повернули `-1` рівно **`97`** запитів.
   - *Прояв:* бінарний пошук відкидає половини масиву навмання, ігноруючи реальне розташування елементів.

---

### Завдання 3 · Пошук межі (`b = 0`)
- **Індекс першого входження X (`"А-00"`):** індекс = `0`, порівнянь = `17`.
- **Кількість елементів, рівних X:** `45` (знайдено через два виклики `LowerBound` за **`33` порівняння** проти **`100 000` порівнянь** при лінійному підрахунку).
- Кількість порівнянь не залежить від того, скільки елементів дорівнює `X`, оскільки `LowerBound` завжди виконує фіксовану кількість поділів діапазону навпіл ($\lceil \log_2 N \rceil = 17$) до повного звуження меж.
- **Перевірка на умові, не узгодженій з порядком (перший код із цифрою `'7'`):** `LowerBound` повернув індекс `98953` (`"Я-70"`, за `17` порівнянь), тоді як реальний перший такий елемент має індекс `254` (`"А-07"`). Відповідь **неправильна**, тому що умова наявності цифри `'7'` не є монотонною відносно алфавітного порядку масиву.

### Завдання 4 · Додатковий варіант пошуку (`c = 1`)

| Запит | Класичний бінарний (порівнянь) | Без рівності в циклі (порівнянь) |
| :--- | :---: | :---: |
| Значення X (`"А-00"`) | `12` | `18` |
| Перший елемент (`"А-00"`) | `12` | `18` |
| Відсутнє значення (`"Я-99"`) | `17` | `17` |

У циклі виконується лише одна перевірка (`cmp(a[mid], target) < 0`) замість двох перевірок на рівність і напрямок, тому порівнянь на крок стало менше, але цикл не може вийти достроково при випадковому влучанні в `mid` і завжди робить усі кроки до звуження діапазону в один елемент плюс одну фінальну перевірку.

### Завдання 6 · Висновки

1. **Зміряна точка окупності проти лекційних 34:** Моє зміряне число (~750 запитів) суттєво більше за теоретичні 34. Теоретична оцінка враховує лише кількість абстрактних порівнянь елементів і ігнорує реальну вартість апаратних операцій: лінійний пошук читає пам'ять послідовно (чудово працює префетчінг кешу CPU), тоді як сортування `100 000` посилань на рядки через делегат `Func` викликає багато промахів кешу та накладних витрат на виклики функцій.
2. **Питання для бінарного пошуку, на які не відповідають хеш-структури:**
   - Знайти перший елемент, більший або рівний заданому значенню (`LowerBound`, пошук найближчого сусіда), коли точного збігу в базі немає.
   - Порахувати кількість елементів у заданому діапазоні значень `[X; Y]` без перебору всього масиву.
3. **Потік даних зі зміною масиву після кожного запиту:** У такій задачі найкраще вибрати **хеш-структуру (`HashSet` / `Dictionary`)**. Сортування з бінарним пошуком провалиться, бо кожна вставка або видалення вимагатиме зсуву елементів або повторного сортування за $O(N \log N)$, а перебір буде занадто повільним на великих обсягах, тоді як хеш-таблиця дає $O(1)$ і на пошук, і на оновлення.
