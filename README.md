# Лабораторна робота №4
N = 16, K = 1, a = 1, b = 0, c = 1

### Завдання 2 · Особливості хибного варіанта вилучення
Хибний варіант (цикл від початку з `RemoveAt(i)`) пропустив елементи `9`, `-6` та `6`. Це сталося через те, що після видалення елемента всі наступні зміщуються вліво на 1 позицію, а лічильник `i` збільшується, через що елемент, який зсунувся на місце видаленого, пропускається перевіркою.

### Завдання 5 · Таблиця часу та висновки

| Що міряємо | Час, мс |
| :--- | :--- |
| 100 000 × Add(x), список без заданої місткості | 0 |
| 100 000 × Add(x), new List<int>(100000) | 0 |
| 100 000 × Insert(0, x) | 268 |
| 1 000 × Contains(значення, якого немає) у списку з 100 000 елементів | 9 |

**Відповіді на запитання:**
1. **У скільки разів Insert(0, x) повільніший за Add(x) і чому:** `Insert(0, x)` забирає 268 мс, що в сотні разів повільніше за `Add(x)` (0 мс). При вставці на початок масиву потрібно зміщувати всі наявні елементи праворуч ($O(N)$ для кожного виклику, загалом $O(N^2)$), а `Add(x)` додає елемент у кінець за амортизований час $O(1)$.
2. **Чому заздалегідь задана місткість дає виграш:** Попереднє виділення пам'яті `new List<int>(100000)` усуває витрати на багаторазове виділення нових масивів у пам'яті та копіювання старого вмісту при переповненні заумовчанням.
3. **Чому Contains тисячу разів помітно довший за сто тисяч Add:** Метод `Contains` здійснює лінійний пошук ($O(N)$). Виклик `Contains` 1 000 разів для 100 000 елементів виконує близько $1000 \times 100000 = 10^8$ операцій порівняння, що вимагає набагато більше часу (9 мс), ніж додавання елементів в кінець.
